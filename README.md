# KARY..MO — موقع المملكة (Mini App لبوت @Karey3_bot)

## الموقع بيعمل إيه
- **بيع وشراء قلاع:** الزبون بيملا الفورم، والموقع بيرسم **صورة إعلان** أوتوماتيك من بياناته (الإحصائيات، مواصفات القلعة، الأبطال بصورهم والأهلة، رقم العرض، العتاد).
- صورة الإعلان تستخدم القالب البنفسجي والذهبي في `site/castle-ad-template.jpg`: تعرض الأبطال المختارين فقط، بإطار لكل بطل وأسهم تحت عناوين القسمين. الأبطال المحددون في الكود يظهرون في القسم الرئيسي، وباقي المختارين في قسم الأبطال الإضافيين (حتى 10)؛ وإذا لم يُختر أبطال لقسم يظهر «لا يوجد». تتوسع البطاقات لتملأ المساحة المتاحة مع صور الوجوه والأهلة، مع الحفاظ على زخرفة القالب الأصلية.
- الصورة بتوصلك على تليجرام، و**تحتها رسالة** فيها رقم العرض ورقم واتساب البائع ورابط التواصل والروابط والموارد والسعر وقائمة الأبطال كاملة.
- **رقم العرض** هو آخر 5 أرقام من واتساب الزبون.
- **البوتات:** بيعرض الباقات والأسعار. **الموارد والأحداث:** بيحوّلوا الزبون على واتساب.

قسم الباقات ظاهر للزبائن، أما `site/admin.html` فهي لوحة خاصة بحساب الأدمن على تيليجرام. تتيح تعديل رسالة الترحيب والأسعار وأسئلة فورم القلاع، ومراجعة طلبات الاشتراك. إرسال إعلانات القلاع من GitHub Pages يستخدم خادم Node على Render؛ تشغيل لوحة الإدارة يظل إعدادًا منفصلًا موضحًا في `SETUP_GUIDE.md`.

## الملفات
| الملف | وظيفته |
|---|---|
| `site/index.html` | الموقع العام وفورم بيع وشراء القلاع |
| `site/admin.html` | لوحة الإدارة الخاصة بالأدمن على تيليجرام |
| `site/runtime-config.js` | رابط API الذي يربط نموذج الإعلانات بخادم Render |
| `site/hero.jpg` | صورة المملكة |
| `site/castle-ad-template.jpg` | خلفية قالب إعلان القلعة |
| `site/hero-portraits/` | صور وشوش الأبطال (اسم الملف بالإنجليزي؛ الموقع يدعم وجود الصور هنا أو في جذر الموقع) |
| `cloudflare-worker.js` | Worker قديم لوظائف Mini App الاختيارية؛ إرسال الإعلانات يستخدم Render |
| `server.js` | نفس الشغل بس لو هتشغّل الموقع على سيرفر Node (Render / Railway / جهازك) |
| `get-chat-id.js` | بيجيبلك الـ Chat ID بتاعك |

> ⚠️ **ما ترفعش ملف `.env` على GitHub أبدًا**، ولا تبعته لحد، لأن فيه توكن البوت.
> لو سبق ورفعت الموقع وفيه توكن مكتوب في كود الصفحة، ألغِ التوكن القديم من BotFather وأنشئ واحدًا جديدًا، ثم حدّثه كـ Secret في الاستضافة.

## إرسال الإعلانات من GitHub Pages باستخدام Render
GitHub Pages يعرض الملفات فقط؛ لذلك نموذج الإعلان يرسل إلى خادم Node منفصل. ملف `render.yaml` يجهز الخادم ومسار فحص الصحة ويسمح بطلبات صفحة GitHub المحددة فقط.

1. ارفع المشروع إلى GitHub من جذر المستودع، مع استبعاد `.env`.
2. في Render أنشئ **Blueprint** من المستودع وطبّق إعدادات `render.yaml`.
3. أضف `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` كـ **Secrets** في Render؛ لا تضعهما في ملفات `site/`.
4. بعد نشر الخدمة، تأكد أن عنوانها هو `https://kary-mo-telegram-api-056-arch.onrender.com`. إذا أعطاك Render عنوانًا مختلفًا، حدّث `site/runtime-config.js` ليستخدمه وينتهي بـ `/api/telegram/order`.
5. ارفع ملفات `site/` إلى GitHub Pages، بما فيها `runtime-config.js`، وانتظر اكتمال النشر.
6. افتح `https://mostafamaray056-arch.github.io/KARY._.MO/` وجرّب إرسال إعلان اختباري.

لا تشارك توكن البوت في المحادثات أو تضعه في GitHub. الخدمة المجانية قد تدخل وضع السكون، لذلك قد يتأخر أول طلب بعد فترة خمول.

### إزاي تجيب الـ Chat ID
ابعت `/start` للبوت، وبعدين افتح الرابط ده في المتصفح، بعد ما تحط التوكن مكان `TOKEN`:
`https://api.telegram.org/botTOKEN/getUpdates`
هتلاقي `"chat":{"id":123456789` والرقم ده هو الـ Chat ID.
ولو معاك Node على جهازك، ممكن بدل ده تشغّل `node get-chat-id.js`.

## تشغيل محلي
1. أنشئ `.env` من `.env.example` وأضف قيم تيليجرام الخاصة بك محليًا.
2. شغّل `node server.js` وافتح `http://localhost:3000`.
